The problem

Most boards let you drag anything, anywhere.

  • 1 A card moving to "In Progress" doesn't check what it's waiting on — nothing stops work from starting before its prerequisites are ready.
  • 2 Teams end up relying on memory, sticky notes, or a Slack message to know what's actually safe to start.
  • 3 Weave enforces the order for you — a task can't move until what it depends on is marked done.
How it works

Three steps, one rule.

Set what a task depends on. Try to jump the line. Watch it open the moment it's ready.

1

Set dependencies

Pick which tasks need to finish first, right from a dropdown on the card. No separate diagram to maintain.

2

Try to jump ahead

Drag a locked task into "In Progress" and Weave stops it — with a plain-language message, not a silent failure.

3

Watch it unlock

Finish the dependency, and every task waiting on it opens up automatically — no refresh, no manual re-check.

Under the hood

Built on a real dependency engine.

Not a visual trick — an actual graph running underneath every card.

↺

Cycle detection

Rejects dependency chains that loop back on themselves before they ever get saved.

⇄

Lock/unlock propagation

One status change re-checks every dependent task automatically — not just the one you touched.

✎

Built from scratch

Vanilla JS drag-and-drop. No external board library doing the work for us.
